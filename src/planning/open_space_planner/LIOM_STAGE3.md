## 输入输出与约束

入口为 `open_space::OptimizeLiomParkingSegments()`，输入：

- 搜索分段后、由原速度规划生成时间和速度初值的 `vector<TrajectoryPointArray>`。
- 同一份局部 `OccupancyGrid` 地图快照，仅值为 25 的格子允许通行，其他值均视为障碍。
- 地图局部坐标系在轨迹世界坐标系中的位姿 `grid_pose`，必须对应地图快照，不能用每段起点替代。
- 原 `OpenSpace_config`，直接复用 `search_collision_margin`，当前默认 0.4 m。

内部计入地图 origin 的平移和二维旋转，转换到栅格轴坐标求解，输出回原世界坐标。
消息类型、档位和 header 保持不变，每段 relative_time 独立从零开始。
保留搜索的分段数量、前后顺序、换挡位姿；固定各段首尾位置、航向和零速。
同段限制转角和转角速率，停车换挡处允许前后段转角不同；停车调轮时间没有加入总时间。
是否等待调轮到位属于现有执行状态机及下一阶段接入检查的职责。

当前每个等时间节点建立沿本轮参考车身方向的无障碍矩形，四个外扩车身角点辅助变量
共同受同一矩形边界约束，整个凸车身都在该矩形内，而非只查角点是否碰撞。
角点与车辆位姿的几何一致性通过残差惩罚和收敛后残差门限检查。
走廊用占据前缀和作空区域快速判断，必要时用分离轴检查旋转矩形与整块栅格；
四边轮流扩展，每侧最多 1 m。贴边的内部节点允许向相邻一格找安全框，端点不移动。
首轮围绕等时间初值建走廊；残差不达标时递增惩罚，围绕上一轮新解重建走廊。
每轮复用同一地图前缀和，达标并通过完整扫掠后立即结束；不增加 ESDF 或距离障碍代价。

安全余量外扩车身一次，不再给地图叠加相同余量。走廊另有四分之一格数值缓冲。
初值点间余量不足不再提前整段拒绝，能建立安全走廊时交由优化修正。
最终结果必须检查完整矩形车身与整块占据栅格是否相交，
包括车身内部障碍、栅格部分重叠以及节点之间的碰撞；未放松最终门限。
相邻位姿按平移与最短航向角线性插值加密，按车身运动上界额外外扩包络，
保守复核该插值的扫掠；不等同于证明实际控制器跟踪或连续车辆动力学的安全性。

全部段求解和复核通过后才修改 output；任何一段失败，整个输出保持原值，
report.failed_segment 给出失败段索引。尚未在执行链路实现失败回退。

## 历史记录：第三阶段为何使用四圆而不是两圆

以下为第三阶段当时的模型和对照数据；当前矩形走廊已不使用四圆。

参考 `vehicle_model.h` 默认 `n_disc=2`，本适配固定四圆，不增加 YAML 参数。
把外扩矩形沿纵向等分为 N 块，各块的外接圆共同覆盖整个矩形：

`r = 0.5 * hypot((车长 + 2*余量)/N, 车宽 + 2*余量)`。

车长 5 m、车宽 3 m、余量 0.4 m 时，两圆半径约 2.39 m，四圆约 2.03 m。
两者都能完整覆盖车身；四圆减少多占用的空白空间，并非修复两圆固有漏检。
当前走廊使用圆外接的栅格轴对齐方框，比纯圆碰撞更保守，四圆只能部分缓解。
每个节点的圆心辅助变量从 4 个增加到 8 个；整个节点变量从 11 个增加到 15 个，
并非整个优化规模或耗时翻倍。四圆也不代表主动远离障碍，仍只有硬走廊与余量。

同机、相同默认车辆参数、0.1 m / 40x40 m 地图的单次对照结果：

| 场景 | 两圆 | 四圆 |
| --- | --- | --- |
| 宽阔前进+倒车两段 | 成功，111 ms | 成功，116 ms |
| 净宽约 4.3 m 直通道，矩形余量检查通过 | 走廊构造失败 | 成功，65 ms |
| 弓形绕行一个占据格 | 成功，216 ms | 成功，330 ms |

这是合成场景单次离线测量，不是周期耗时上限或普遍性能结论。
两圆的通道失败是在求解前保守拒绝，不是碰撞漏检或 IPOPT 求解失败。
测试中无障碍优化会拉直穿过绕行障碍，加入走廊后结果通过完整车身扫掠复核。
因此当时版本保留四圆；随后真实搜索绕障测试暴露了圆的端部过度包络问题，
第四阶段第三项改用矩形走廊。新模型仍可能在紧窄或斜向通道保守拒绝。

## 简单复现

无需 ROS master，不发布控制话题；使用已有 ROS 消息、IPOPT 和 ADOL-C 环境。
独立构建避免覆盖 UGV 正常 build/devel：

```bash
source /opt/ros/noetic/setup.bash
source /home/zhq/UGV/devel/setup.bash
liom_check_dir=$(mktemp -d /tmp/ugv-liom-grid-XXXXXX)
cmake -S /home/zhq/UGV/src/planning/open_space_planner -B "$liom_check_dir" \
  -DOPEN_SPACE_BUILD_LIOM=ON -DPYTHON_EXECUTABLE=/usr/bin/python3 -DCMAKE_BUILD_TYPE=Release
cmake --build "$liom_check_dir" --target liom_segment_check liom_grid_check -j2
export LD_LIBRARY_PATH="$liom_check_dir/devel/lib:$LD_LIBRARY_PATH"
(cd "$liom_check_dir" && ctest -R '^liom_(segment|grid)_check$' --output-on-failure)
```

`liom_grid_check` 的场景按默认 openspace.yaml 车辆尺寸设计。
它检查：多段位姿和零速端点、允许停车转角不连续、车内小障碍、未知格、
非 25 栅格、换挡点断开、后段失败输出不变、安全余量、部分栅格重叠、
平移/旋转中间扫掠、地图边界、地图尺寸、窄通道和优化切角。
`liom_segment_check` 继续检查无障碍接口的动力学及输入输出回归。
